# DigitalLab · 实验室设备档案

设备目录、手机扫码档案、管理员录入、SOP、PDF说明书与照片、内部购买资料、维护记录、Excel导入，以及90×60mm设备信息标签。默认中文，适用于100台以内设备。

## 本地查看

运行环境：Node.js 24、npm；数据库使用 PostgreSQL。克隆 [DigitalLab](https://github.com/Yabaisaka/DigitalLab) 后，将 `.env.example` 复制为 `.env.local`，设置初始管理员邮箱和至少 12 位的密码；开发数据库连接填 `postgresql://digitallab:local-development-only@localhost:54329/digitallab`。需要示例设备时设置 `SEED_DEMO=true`。

```sh
npm ci
npm run local:db
```

保持数据库终端运行，在另一个终端执行：

```sh
npm run db:init
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)，使用自己配置的 `ADMIN_EMAIL` 和 `ADMIN_PASSWORD` 登录。开发数据库监听 54329 端口，本地数据位于 `.local-db/`；此开发数据库配置只用于本机。

如果未配置本地文件，复制`.env.example`为`.env.local`，设置数据库连接、初始管理员邮箱和至少12位的密码。`APP_ORIGIN`须与浏览器地址完全一致（协议、域名和端口），否则写操作会被拒绝。

## 公网部署：Linux＋Docker Compose

仓库包含通用 Docker Compose 部署配置；服务器凭据、实际设备资料和附件由部署者自行配置。

1. 准备域名与Linux服务器，安装Docker Engine及Compose插件。域名A/AAAA记录指向服务器，开放80、443端口；不要开放数据库端口。建议至少2核、2GB内存，构建时4GB更稳妥。
2. 在服务器克隆此仓库；`.env.example` 是配置模板，实际 `.env`、数据库及上传资料不纳入版本管理。
3. 复制`.env.example`为`.env`，修改`POSTGRES_PASSWORD`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`及`SITE_HOST`（只填域名，如`lab.school.edu`）。数据库密码建议用随机字母数字，至少24位；如使用特殊字符，需要在连接URL中进行URL编码。`SEED_DEMO=false`保持关闭。
4. 启动数据库，初始化，然后启动应用与HTTPS入口：

```sh
docker compose up -d db
docker compose --profile tools build app init
docker compose --profile tools run --rm init
docker compose up -d --build app caddy
docker compose ps
```

Caddy自动申请HTTPS证书。Compose会覆盖应用的`APP_ORIGIN`为`https://${SITE_HOST}`并启用安全Cookie。正式部署不会使用本地验收账号、数据库或附件。首次数据库初始化之前不要启动应用。

5. 登录后台“实验室设置”，填写实验室名称、标识与正式HTTPS网址。用手机扫描验证二维码，在该公网页面登录管理员并确认扫码成功。验证完成后才可导出正式标签；修改网址会清除验证状态。
6. 在正式网址上验证设备发布、公开说明书下载、成员查看内部资料，然后打印一张样张，实测90×60mm尺寸和手机扫码效果。

如修改`.env`，使用`docker compose up -d --force-recreate app`更新运行环境。不要将`docker compose down -v`作为常规停止命令，它会删除持久化数据。

## 录入与使用

- **基本资料**：名称、唯一设备编号、分类、型号、厂家、负责人及电话、主要参数、运行状态。按单个实验室管理，不填写序列号或房间位置。分类从下拉菜单选择，包含常用类型与已有分类。设备创建时默认为草稿。首次保存后才能上传附件。
- **操作资料**：一台设备最多20套SOP，分别记录名称、版本、适用场景、专有提示、步骤、来源和待核对事项；扫码页可切换使用方式。设备通用提示与标签短提示适用于所有方式。正文支持Markdown及实时预览。旧的单套SOP无损显示为“通用操作”。缺失内容显示“待补充”。
- **SOP文件导入**：在“操作SOP”下载JSON模板或AI生成Skill，将规范化JSON上传后校验和预览。合并按稳定SOP标识更新，其余保留；替换会列出移除项。两者都会更新通用使用前提示和标签短提示，设备其他资料保留。核对后应用到表单，再保存档案。服务端拒绝未知格式、多余字段、重复标识或名称、错误来源链接、超长提示和过大文件。仅管理员可导入；JSON文件不会作为公开附件保存。
- **AI生成Skill**：网页的“GitHub安装Skill”入口指向[公开仓库](https://github.com/Yabaisaka/lab-sop-generator)。运行`npx skills add Yabaisaka/lab-sop-generator --skill lab-sop-generator`安装，向agent提供设备资料、使用场景和说明书，调用`$lab-sop-generator`生成`.sop.json`。仓库包含SKILL.md、格式说明、JSON Schema、示例和无第三方依赖的Python校验器；未知参数必须标为“待补充”，来源与待核对事项一并保留。项目仍保留原ZIP下载地址以兼容旧链接；本地分发文件由`node --import tsx scripts/build-sop-skill.ts`更新，格式以`lib/sop.ts`为准。Skill 在上述独立仓库维护；调整协议时同步更新两个仓库中的格式说明、Schema、示例和校验器。
- **内部资料**：购买日期、人民币价格、购买渠道、供应商或店铺名称、店铺或订单链接、可选销售或客服联系方式、保修期限、内部备注、维护记录。日期录入统一为yyyy/mm/dd，也支持日历选择；网购设备无需填写电话。
- **附件**：PDF、PNG、JPEG、WebP，单个最大20MB。纸质资料可扫描为PDF。合同和发票强制为内部附件；说明书、其他资料可选择公开或内部，照片也可选择可见范围。附件上传及删除立即保存。
- **发布**：勾选“发布至公开目录”并保存。撤销发布后只有管理员可见。停用设备保持档案地址，但页面提示当前状态。
- **Excel**：下载模板，删除示例行，填入真实信息。每次最多200行、2MB，只接受`.xlsx`，不接受公式。先上传预览，修正全部错误后确认导入。导入事务整体成功或整体回滚；所有新记录为草稿。
- **账号**：支持账号ID或邮箱登录，ID不区分大小写。管理员可创建账号、任命或撤销其他管理员。没有公开注册。账号密码至少6位；角色变更、重置密码或停用账号会撤销已有会话。当前管理员无法停用自己或取消自己的管理员权限；系统保留至少一位启用管理员。会话12小时有效，登录按账号限制15分钟内最多10次尝试。

负责人及厂家技术支持电话会公开显示；购买渠道、链接及销售或客服联系方式仅成员可见。录入时请使用适合公开的联系方式。管理员编辑有版本冲突保护；出现“已被其他人更新”时，先保留自己修改的内容，再刷新页面合并。

## 标签制作

后台“信息标签”提供SVG、90×60mm PDF、A4批量PDF。PDF嵌入本地Noto中文字体，无需联网。SVG使用中文字体文本，使用支持中文的浏览器或设计软件打开。

标签内容：实验室名称、编号、名称或标签简称、型号、负责人、电话、最多两条确认过的重要提示、25mm二维码与备用网址。正文不低于8pt。长内容超出容纳范围时，会提示修改简称或文字，不会静默缩小字号。

- **预览模式**：带“预览 · 请勿张贴”；没有域名时二维码指向不可访问的`example.invalid`。草稿和示例设备仅可预览。
- **正式模式**：要求真实公网HTTPS域名、扫码验证已完成、设备已发布且未标记为示例。
- **A4**：每页8张，2列×4行，6mm间距，适用于整张A4不干胶或印刷裁切，不适配任意预切标签纸。
- **打印**：选择“100% / 实际大小”，关闭自动缩放。建议哑光覆膜不干胶，结合仪器清洁剂、温度和表面材质选择耗材；不要遮挡原厂铭牌、散热口或安全警示。
- **网址**：每台设备地址为`/e/{不可变标识}`；修改名称、编号和资料不会改变二维码。正式印刷后应长期保留域名，换服务器只需保持同一域名与数据库。

## 备份与恢复

数据库和上传文件分别保存在Compose的`database`、`uploads`卷中。两个部分必须一起备份。

```sh
bash scripts/backup.sh
```

脚本短暂停止应用写入，生成同一时刻的`database.dump`和`uploads.tar.gz`，完成后自动恢复应用。输出目录默认`backups/UTC时间戳/`，权限仅当前用户可读。建议每天运行，保留至少最近30天副本，并复制到另一台机器或加密存储。

恢复会替换当前数据库，请先备份当前状态：

```sh
bash scripts/restore.sh backups/实际备份目录 --confirm-replace
```

恢复数据库、附件和文件权限后重新启动应用。如恢复失败，应用保持停止以避免展示不一致资料。文件卷中可能保留没有数据库引用的旧附件，但下载接口不会提供这些文件。恢复后检查登录、公开说明书、内部合同和设备固定网址。

初始管理员密码不会被再次运行初始化脚本覆盖。正常重置密码请使用“成员管理”；首次上线后可从`.env`移除`ADMIN_PASSWORD`并妥善保管独立凭据，再次使用初始化工具时临时提供。

## 验证与维护

```sh
npm run typecheck
npm test
npm run build
npm audit --omit=dev
npm run test:e2e
```

端到端测试要求：运行本地演示数据库、初始化示例记录、本地网站可用、已安装Chrome。测试只应用于本地验收环境，会创建并清理测试记录。测试数据库必须为本地演示配置，不要对正式网址运行。页面截图保存在`artifacts/`，失败追踪保存在`test-results/`。

健康接口`/api/health`仅返回可用状态，不泄露连接信息。诊断部署使用`docker compose logs --tail=100 app caddy db`。数据表由`npm run db:init`幂等建立；未来修改数据库结构时需增加显式迁移，当前版本不自动更改已有列。

工程结构：`app/`网页与接口，`components/`界面，`lib/`权限、校验、数据库和导出，`scripts/`初始化与备份工具，`assets/fonts/`PDF中文字体。上传文件不放在`public/`，只能通过权限校验后的文件接口下载。

首版不含预约、使用登记、在线报修或纸质资料OCR。
